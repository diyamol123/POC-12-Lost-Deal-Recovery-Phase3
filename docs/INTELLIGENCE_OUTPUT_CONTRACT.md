# Intelligence Output Contract

## Project

**POC-12 — Lost Deal Reason & Recovery Intelligence**

## Approved Track

**Track A — Comparative Intelligence**

## Data Version

`phase3-v1.0.0`

## Method Version

`1.0.0`

---

## 1. Intelligence Results Contract

The primary output is:

`data-science/outputs/intelligence_results.json`

The output contains one result object for each included category.

### Required Fields

Each result object contains:

- `result_id`
- `result_type`
- `record_id`
- `entity_id`
- `group_key`
- `period_start`
- `period_end`
- `metric_name`
- `result_value`
- `result_unit`
- `result_category`
- `priority_rank`
- `finding`
- `evidence`
- `method_version`
- `data_version`
- `generated_at`
- `quality_status`
- `limitation`

### Field Definitions

| Field | Meaning |
|---|---|
| `result_id` | Stable identifier for the comparative result |
| `result_type` | Type of analytical result |
| `record_id` | Record-level reference; null for group-level results |
| `entity_id` | Entity-level reference; null for group-level results |
| `group_key` | Category being compared |
| `period_start` | Period start when applicable; null for the current aggregate |
| `period_end` | Period end when applicable; null for the current aggregate |
| `metric_name` | `total_deal_value` |
| `result_value` | Total deal value for the group |
| `result_unit` | `currency_unspecified` |
| `result_category` | Deterministic rank label |
| `priority_rank` | Rank based on total deal value |
| `finding` | Plain-language descriptive finding |
| `evidence` | Supporting count, average, contribution, and record IDs |
| `method_version` | Analytical method version |
| `data_version` | Canonical data version |
| `generated_at` | UTC generation timestamp |
| `quality_status` | Validation status |
| `limitation` | Important interpretation boundary |

---

## 2. Evidence Contract

The `evidence` object contains:

- `record_count`
- `average_deal_value`
- `percentage_of_total_value`
- `record_ids`

These fields allow each comparative finding to be traced back to the canonical records.

---

## 3. Intelligence Summary Contract

The summary output is:

`data-science/outputs/intelligence_summary.json`

### Required Fields

The summary contains:

- `project_id`
- `project_title`
- `approved_track`
- `primary_question`
- `decision`
- `data_version`
- `method_version`
- `result_count`
- `key_findings`
- `priority_items`
- `validation_result`
- `weak_case_review`
- `important_limitations`
- `generated_at`

---

## 4. Priority Item Contract

Each priority item contains:

- `rank`
- `group`
- `total_deal_value`
- `percentage_of_total_value`

Priority order is determined only by:

1. Total deal value descending
2. Category name ascending for deterministic ties

No subjective score or business ranking is added.

---

## 5. Validation Contract

The summary must report:

- Overall validation pass/fail
- Contribution total
- Groups at the minimum-size threshold

The detailed validation evidence is stored in:

`data-science/outputs/validation_metrics.json`

---

## 6. Weak-Case Contract

Weak-case evidence is stored in:

`data-science/outputs/weak_case_review.json`

The review identifies:

- Groups at the minimum sample-size threshold
- Leave-one-out sensitivity findings
- Highest-value record
- Interpretation limitations

---

## 7. Versioning

All analytical outputs must identify:

- `data_version = phase3-v1.0.0`
- `method_version = 1.0.0`

A change to the canonical analytical input requires a corresponding version review.

A material change to the calculation method requires a method-version update.

---

## 8. Quality Status

The current generated results have:

`quality_status = validated`

This indicates that the output passed the implemented Track A validation checks.

---

## 9. Interpretation Boundary

The output is descriptive intelligence.

It must not be interpreted as:

- A causal analysis
- A predictive model
- A probability of recovery
- A forecast
- A population-wide estimate
- A guarantee of business impact

The output describes patterns observed in the approved synthetic canonical sample.

---

## 10. Reproducibility

The output must be regenerated by executing the analytical scripts rather than manually editing JSON files.

Primary execution:

`data-science/scripts/run_comparative_intelligence.py`

Validation:

`data-science/scripts/validate_analytical_track.py`

Weak-case review:

`data-science/scripts/review_weak_cases.py`

Export:

`data-science/scripts/export_intelligence_results.py`

All scripts use the approved canonical CSV as their analytical source.
